# Agent instructions for einring

Before making changes, read the shared WIT guidance in `+wit/AGENTS.md` and `+wit/README.md`, then read `+intent/intent.md`, `+intent/decisions.md` and `+intent/tests.md`. Decisions are binding; change them by adding a dated entry, not by silently deviating.

## Commands

- `pnpm install` - workspace install (pnpm 10, Node >= 22.13 or >= 23.4; Node 23.0–23.3 is unsupported because `node:sqlite` is unavailable)
- `pnpm tokens:build` - must run before `apps/app` builds (generates `packages/tokens/build/css/tokens.css`)
- `pnpm lint` / `pnpm lint:fix` - Biome (format + lint)
- `pnpm typecheck`, `pnpm test`, `pnpm build` - all workspaces
- `pnpm --filter @einring/bff test` - BFF tests (Fastify `inject`, in-memory SQLite). On Node 23.x < 23.4 prefix with `NODE_OPTIONS=--experimental-sqlite`
- `pnpm --filter @einring/app android:sync` - web build + `cap sync android`; Gradle needs `JAVA_HOME` (a full JDK with `bin/jlink.exe`, preferably Android Studio's JBR, not an IDE extension JRE) and `ANDROID_HOME`

## Rules

- UI styling uses only token variables from `@einring/tokens/css`; no hard-coded colours, spacing or font sizes. New tokens go into `packages/tokens/src` (DTCG format, primitive -> semantic).
- Every user-facing string goes through `react-i18next`; add keys to both `de.json` and `en.json`.
- Nextcloud credentials never leave the BFF; the app only ever holds the Authentik access token.
- BFF response shapes are mirrored in `apps/app/src/api/types.ts`; keep them in sync.
- Acceptance criteria for new features go into `+intent/tests.md` before implementation.
- `apps/app/android/` is generated by Capacitor; only `AndroidManifest.xml`, `build.gradle` and resources are hand-edited.
